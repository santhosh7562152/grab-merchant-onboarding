# Grab Merchant Onboarding – Requirements to Backlog

## Project Overview

This project demonstrates a Business Analyst workflow for improving the restaurant merchant onboarding process for GrabFood.

The project focuses on understanding business problems, gathering requirements, designing business process flows, creating user stories, and managing development tasks using Jira.

**Project Role:** Business Analyst

**Project Type:** Business Analysis / Agile Project Management

## Problem Statement

Manual restaurant document verification and application tracking can cause delays in the merchant onboarding process.

This project proposes a simplified onboarding workflow to improve document submission, verification, application approval, and status tracking.

## Project Objectives

- Understand business requirements.
- Identify onboarding process challenges.
- Create a business process flow diagram.
- Develop user stories and acceptance criteria.
- Create and prioritize a Jira backlog.
- Organize tasks into two development sprints.

## Tools & Technologies

- Jira – Agile project management and sprint planning.
- Google Docs – Business requirements documentation.
- Draw.io – Business process flow diagrams.
- Notion – Project documentation (if used).
- ChatGPT – AI-assisted requirement drafting and review.

## Project Deliverables

1. Business Requirements Document (BRD).
2. Stakeholder Interview Questions and Assumed Answers.
3. Business Process Flow Diagram.
4. Eight User Stories.
5. Acceptance Criteria.
6. Jira Product Backlog.
7. Sprint 1 and Sprint 2 Planning.
8. Jira Board Screenshots.

## Agile Methodology

The project uses an Agile Scrum approach with two proposed sprints:

- Sprint 1: Essential merchant registration, document submission, verification, and approval.
- Sprint 2: Application tracking, rejection feedback, document re-upload, and notifications.

## Important Note

This is an independent portfolio case study based on hypothetical business requirements and assumptions. It is not an official Grab project and does not represent Grab's internal systems or policies.
